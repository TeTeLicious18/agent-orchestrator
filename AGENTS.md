# Repository guide for coding agents

Control plane plus agent runtime for a fleet of autonomous AI agents running on Azure VMs
and network PCs. Read this before changing anything.

## Layout

| Path | What lives there |
| --- | --- |
| `orchestrator/` | FastAPI control plane: routing, leasing, workflows, audit, metrics |
| `orchestrator/static/` | Dashboard. Plain JS, no build step, no framework |
| `agent_node/` | Runtime installed on each machine |
| `agent_node/adapters/` | Execution backends behind one `Adapter` protocol |
| `agent_bridge/` | Local service that exposes Foundry agents over the framework bridge contract |
| `deploy/` | PowerShell provisioning and startup scripts |
| `tests/` | Pytest suite, runs in under two seconds |

## Commands

```bash
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q                 # the inner-loop gate; keep it green
python -m uvicorn orchestrator.main:app --host 0.0.0.0 --port 8000
python -m agent_node.runner --config agent_node/config.yaml
```

Optional extras, each enabling one adapter capability: `requirements-foundry.txt` (model
access), `requirements-browser.txt` (Playwright), `requirements-desktop.txt` (PyAutoGUI),
`requirements-office.txt` (openpyxl).

## Conventions

* Python 3.11+, `from __future__ import annotations`, built-in generics, `X | None`.
* Comments explain *why*, never *what*. One line is usually enough.
* Docstrings state the trust boundary or the failure mode, not the signature.
* Every SQL statement is parameterised. No string interpolation into queries.
* The dashboard builds DOM nodes through helper functions. `innerHTML` is never used.
* Adapters implement `handles()`, `capabilities()` and `execute()`, nothing else is assumed.

## Security invariants

These are load-bearing. Changing one without a test is a regression.

* Filesystem access resolves inside a workspace root; absolute paths, UNC paths and
  traversal are rejected before any file is touched.
* Shell and application launches come from allow-lists that map a name to a fixed argv.
  The model never supplies command text, and `shell=False` everywhere.
* `open_file` uses an extension allow-list, so an executable can never be handed to the
  shell through a file association.
* HTTP and browser navigation block loopback, link-local and cloud metadata addresses.
  `169.254.169.254` in particular holds the node's managed identity token.
* Agent requests are HMAC-signed over version, method, path, timestamp, nonce and body
  hash. The agent id in the path must match the signing identity.
* No model key exists anywhere. Nodes authenticate to Foundry with their own managed
  identity; the orchestrator sends only deployment coordinates.

Two risks are accepted and documented rather than eliminated: web page text re-enters the
planning loop and is attacker-controlled, and a program started by `run_code` is not bound
by the file sandbox. Both are opt-in per node.

## Configuration

Secrets live in `.env` (control plane) and `C:\hecaton\node.env` (each node). Both are
gitignored and must never be committed. `*.example` files show the shape; real values are
generated by `deploy/start-laptop.ps1`.

`orchestrator/config.py` calls `load_dotenv()`, so a local `.env` leaks into any process
started from the repository root. `tests/conftest.py` sets its environment explicitly,
including empty Foundry endpoints, so the suite stays hermetic. Preserve that when adding
settings.

## Environment traps

Verified the hard way; they cost hours if rediscovered.

* On Windows, `python` often resolves to the Microsoft Store stub. Call the interpreter by
  full path, for example `C:\venvs\hecaton\Scripts\python.exe`.
* Keep virtual environments and the SQLite database outside OneDrive-synced folders.
  `ORCH_DB_PATH` must point somewhere local or the database will corrupt.
* `azure-ai-projects` 2.x differs from the 1.x documentation: agents are named and
  versioned, `ConnectedAgentTool` does not exist, and a prompt agent is invoked through the
  Responses API with `extra_body={"agent_reference": {"type": "agent_reference", "name": ...}}`.
* Long autonomous runs exceed the default lease. Set `ORCH_LEASE_SECONDS` well above the
  expected task duration or the reaper will re-queue work that is still running.

## Changing things

* Adding an adapter capability means: the tool schema, the dispatch branch, a capability
  string, the config wiring in `agent_node/runner.py`, and a test for the guard.
* Adding an action namespace usually means a `CAPABILITY_HINTS` entry in
  `orchestrator/routing.py` so submissions route without explicit capabilities.
* Run `python -m pytest -q` before proposing a change. It is fast enough that there is no
  excuse to skip it.
